# Итоговый отчёт по ревью и исправлениям Borin — задание 5

## 1. Цель и объём

Проведён статический анализ предоставленного архива Borin и внесены приоритетные исправления, направленные на устранение блокирующих дефектов конфигурации, ORM, авторизации и запуска приложения. Схема БД для сверки взята из `database/db.sql`. ER-диаграмма, Postman-коллекция и тестовый каталог в исходном архиве отсутствовали.

## 2. Результат пункта 5.1 — сводная таблица

Полная таблица замечаний с приоритетами, затронутыми файлами и предложениями по исправлению находится в [`findings_summary.md`](findings_summary.md). Главные блокирующие проблемы исходного проекта:

- секреты и пароль БД находились в `.env`, который был включён в архив;
- конфигурация содержала статический секретный ключ и некорректную настройку подключения;
- `run.py` включал debug и внешний bind по умолчанию;
- ORM-модели содержали синтаксически допустимые, но некорректные объявления колонок/связей и расходились с SQL-схемой;
- обработчики авторизации были сломаны логически: затенение endpoint-функции, неверные проверки пользователя, неверные имена атрибутов;
- фабрика приложения подключала нерабочие View-модули и выполняла лишние действия с БД при старте.

## 4. Результат пункта 5.3 — отчёт и подготовка к защите

Данный файл является итоговым отчётом. Ключевые решения, ограничения и сценарий защиты приведены ниже.

### Проверки

| Проверка | Результат |
|---|---|
| Компиляция `python -m compileall -q app run.py` | Успешно, exit code 0 |
| AST-разбор Python-файлов | 54 файла разобраны без синтаксических ошибок |
| Наличие шаблонов, используемых исправленными web-маршрутами | Проверено, все 9 целевых шаблонов найдены |
| Импорт и создание Flask-приложения | Не подтверждено: Flask и расширения не установлены в окружении |
| HTTP smoke/integration tests | Не запускались: отсутствуют установленные зависимости и тестовая БД |
| Подключение к PostgreSQL | Не проверено: сервер и учётные данные для тестового окружения не предоставлены |

Установка пакетов из PyPI была предпринята, но сеть/доступ к индексу пакетов недоступны. Поэтому результаты компиляции и AST нельзя трактовать как подтверждение полного runtime-тестирования.

### Ограничения и оставшиеся работы

- Исходный проект содержит параллельные реализации в `app/blueprints/` и `app/views/`. Исправленная фабрика подключает только исправленные web/auth Blueprint; старые View-модули намеренно не регистрируются, так как часть из них импортирует несуществующие пакеты/классы и использует несовместимые модели.
- CRUD API для всех предметных областей не прошёл интеграционную проверку; модели приведены к SQL DDL, но проекту нужна следующая итерация миграции сервисов/репозиториев и маршрутов.
- Публичная регистрация оставлена только для роли «Пользователь». Создание администратора должно выполняться доверенным административным способом, который ещё требуется реализовать.
- В production нужно задать собственный `SECRET_KEY`, `DATABASE_URL`, HTTPS и выполнить ротацию секретов, попавших в исходный архив.
- Для cookie-based сессий требуется завершить CSRF-защиту форм и AJAX-запросов; аудит всех `innerHTML` в шаблонах также остаётся отдельной задачей.
- В `requirements.txt` указаны допустимые диапазоны версий, но lock-файл и аудит CVE ещё не выполнены.

## 5. Краткий сценарий защиты

1. Показать исходные критические проблемы: `.env` с секретами, пустой `requirements.txt`, некорректные ORM-модели, сломанный login endpoint и debug по умолчанию.
2. Показать `findings_summary.md`: приоритет, файл, предложение и статус исправления.
3. Продемонстрировать историю Git: четыре независимых `fix:` коммита.
4. Объяснить архитектурные решения: единая фабрика Flask, ORM по DDL, корректный `UserMixin`, пароль хранится как хеш, роль администратора нельзя назначить через публичную регистрацию.
5. Показать результаты доступных проверок и честно обозначить, что runtime и PostgreSQL не подтверждены из-за отсутствующих зависимостей/сервера.
6. Завершить планом следующего этапа: тестовая БД, pytest для auth и CRUD, CSRF, единая API-архитектура, миграции и удалённый PR.

## 6. Итог

В рамках задания 5 подготовлена сводная таблица замечаний, внесены четыре отдельные приоритетные правки с `fix:` коммитами и оформлен PR draft. Исправления устраняют найденные блокирующие ошибки в конфигурации, ORM metadata, авторизации и factory/web-слое. При этом полная работоспособность всех бизнес-сценариев ещё не подтверждена: для этого необходимы установка зависимостей, PostgreSQL и интеграционные тесты. Это ограничение явно отражено, чтобы не выдавать статическую проверку за успешный запуск.
