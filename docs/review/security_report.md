# Отчёт по безопасности

## Критические замечания

| Приоритет | Файл / область | Риск и подтверждение |
|---|---|---|
| P0 | `.env` | В архив включён файл с `DATABASE_PASSWORD=12345` и `SECRET_KEY=...`. Секреты нельзя хранить в исходном архиве/репозитории. Считать раскрытыми и заменить. |
| P0 | `app/config.py` | Есть fallback `SECRET_KEY` со статическим значением `production-is-systrm-secret-key-change-me`; при отсутствии переменной среды сессии могут быть подделаны при известности ключа. |
| P0 | `run.py` | Запуск с `debug=True` и `host='0.0.0.0'`; debug нельзя включать на доступном извне сервере. |
| P1 | `app/blueprints/web.py` | `captcha_ok = True` — проверка капчи фактически отключена, несмотря на наличие отдельной реализации капчи. |
| P1 | `web/*.html` | Во всех 11 шаблонах найдены вхождения `innerHTML`; динамическая вставка данных требует экранирования/безопасного DOM API. Сам факт вхождения не доказывает эксплуатируемую XSS, но это приоритетная поверхность проверки. |
| P1 | `web/*.html`, `app/blueprints/web.py` | В шаблонах обнаружены формы и inline event handlers; в просмотренном коде не найдено явной CSRF-защиты/токенов. Для cookie-based сессии изменяющие состояние запросы должны быть защищены CSRF-токеном и/или строгой SameSite-политикой. |
| P1 | `app/blueprints/auth.py`, `app/blueprints/web.py` | Логика входа/регистрации содержит ошибки проверки пользователя и атрибутов; защита от перебора непоследовательна. |
| P1 | `app/__init__.py` | Обработчик 500 возвращает фиксированное сообщение, что лучше раскрытия traceback, но соединение с БД инициализируется/проверяется при создании приложения; необходимо журналировать исключение без секретов. |
| P2 | `app/config.py` | `SQLALCHEMY_ECHO` включается через env; в production SQL-логирование может раскрыть параметры запросов. Проверить, что выключено. |
| P2 | `app/blueprints/web.py` | `/image/<filename>` вручную строит путь и отправляет файл; следует использовать `send_from_directory`/`safe_join` и ограничить доступ к каталогу. |

## Что уже сделано корректно/частично
- `app/auth.py` использует Werkzeug `generate_password_hash` и `check_password_hash`; это предпочтительнее хранения паролей в открытом виде.
- В `web.py` большинство приватных HTML-страниц помечено `login_required`.
- В `admin_view.py` предусмотрена проверка роли администратора, но модуль не импортируется корректно в текущем виде.

## Обязательные меры
1. Немедленно заменить пароль PostgreSQL и `SECRET_KEY`; удалить `.env` из распространяемого архива, добавить `.env.example` без секретов и `.gitignore`.
2. Удалить fallback SECRET_KEY: приложение должно отказываться запускаться без надёжного ключа.
3. Отключить debug и не выставлять встроенный Flask server в production; использовать WSGI-сервер.
4. Включить CSRF-защиту для всех изменяющих состояние запросов, включая AJAX.
5. Проверить каждое место `innerHTML`; предпочитать `textContent`/создание DOM-узлов и валидировать данные на сервере.
6. Включить реальную проверку капчи или удалить ложную проверку; реализовать rate limiting и временную блокировку на сервере.
7. Настроить secure session cookie (`HttpOnly`, `Secure`, `SameSite`) и HTTPS.
8. Ограничить раздачу файлов и протестировать path traversal.
