# Реестр замечаний по маршрутам и базе данных

Приоритет: P0 — блокирует запуск/основной сценарий; P1 — существенная функциональная/защитная ошибка; P2 — качество/неполнота. Маршруты перечислены по статическому просмотру; это не результат успешной регистрации Flask URL map.

| Область / файл | Замечание | Приоритет |
|---|---|---|
| `app/__init__.py` | Инициализация приложения условно зависит от URI БД; фабрика может не вернуть приложение. | P0 |
| `app/config.py` | Не назначается `SQLALCHEMY_DATABASE_URI` для обычных сред; конфликт `ENV`/`FLASK_ENV`, повторные классы. | P0 |
| `app/views/base_views.py` | Методы базового API-класса не совпадают с именами, вызываемыми дочерними view. | P0 |
| `app/views/admin_view.py` | Импорты `run.views.*`/`run.services.*` не соответствуют проекту. | P0 |
| `app/views/items_views.py` | Ошибочные ссылки `Items.add_url_rule`, `itemsListAPI`; detail route привязан к неверному view. | P0 |
| `app/views/customer_view.py` | Ошибочные импорты/имена сервисов и классов, неверные переменные в GET/DELETE, неверная регистрация detail route. | P0 |
| `app/blueprints/auth.py` | Вложенный обработчик `login` не вызывается; `/me` объявлен внутри обработчика; неправильные атрибуты модели. | P0 |

| `app/repository/base_repository.py` | Устаревший `db.select([model])`, commit в цикле обновления. | P1 |

## Выявленные группы endpoint
- `app/blueprints/auth.py`: `/login`, `/register`; `/me` написан внутри обработчика и не регистрируется как самостоятельный маршрут.
- `app/blueprints/web.py`: `/`, `/dashboard`, `/clients`, `/products`, `/materials`, `/operations`, `/specifications`, `/sales-orders`, `/production-orders`, `/admin/users`, `/notes`, `/image/<filename>`, `/logout`, `/api/notes/`.
- Остальные Blueprint: клиенты, номенклатура, заказы, производственные заказы, капча, заметки, спецификации и администрирование.
- `app/views/`: class-based API для клиентов, материалов, спецификаций, заказов, производства, заметок и администрирования; часть регистрации содержит ошибки, поэтому фактические URL могут не появиться.

## Рекомендуемый порядок исправления
1. Зафиксировать единую модель данных и DDL.
2. Исправить ORM и проверить mapper configuration на чистой БД.
3. Утвердить единый набор endpoint и исправить импорты/регистрацию.
4. Ввести схемы валидации входных JSON и единый формат ошибок.
5. Написать тесты для каждого endpoint (успех, неверные данные, несуществующий ID, отсутствие прав).
