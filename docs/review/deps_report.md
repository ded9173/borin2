# Отчёт по зависимостям и документации

## Состояние
`requirements.txt` в архиве пуст (0 байт). `README.md` содержит только `Python 3.14`. Поэтому список используемых библиотек, версии, лицензии и известные CVE по конкретным версиям проверить нельзя. Установка `pip install -r requirements.txt` не установит зависимости.

## Импорты, указывающие на внешние пакеты
По исходникам явно используются Flask, Flask-SQLAlchemy / SQLAlchemy, Flask-Migrate, Flask-Login, python-dotenv, Werkzeug, PostgreSQL driver (вероятно psycopg2 или psycopg), а также Pillow для обработки изображений в `app/puzzle_captcha.py`. Точный драйвер PostgreSQL и минимальные/совместимые версии нужно определить в чистом окружении. Нельзя автоматически считать эти версии проверенными.

## Рекомендации к requirements
- Зафиксировать реально используемые прямые зависимости и проверенные версии после успешного запуска.
- Сформировать lock-файл (например, pip-tools/uv) и регулярно обновлять зависимости.
- Разделить runtime и dev dependencies; в dev добавить pytest и flake8/ruff.
- Выполнить `pip-audit`/`safety` после фиксации версий.
- Не добавлять в requirements транзитивные пакеты без необходимости.

## Документация и артефакты
- README не содержит установки, настройки PostgreSQL, переменных окружения, миграций, запуска и тестов.
- `.env` включён в архив; требуется `.env.example` и исключение `.env` из Git.
- В архиве отсутствуют `tests/`, `scripts/`, `postman_collection.json`, `er_diagram.pdf`.
- `database/db.sql` присутствует, но расходится с ORM-моделями (см. `logic_report.md`).

## Ограничения проверки
Невозможно достоверно сообщить об актуальности/уязвимостях пакетов без заполненного requirements и разрешённого набора версий. Не следует подбирать версии наугад: сначала восстановить окружение и проверить совместимость с Python 3.14 и PostgreSQL.
