# 5.1. Сводная таблица замечаний по результатам ревью

| Приоритет | Затронутый файл | Замечание | Предложение по исправлению / результат |
|---|---|---|---|
| Критично | `.env` | В архиве находились реальные значения `SECRET_KEY` и пароль БД. Их распространение позволяет использовать доступы к окружению. | Удалить `.env` из проекта и истории поставки, добавить `.env.example` без секретов и `.gitignore`. Скомпрометированные значения заменить на стороне БД/окружения. Выполнено в коммите `fix: secure application configuration and runtime defaults`; ротация внешнего пароля остаётся действием владельца БД. |
| Критично | `app/config.py` | Статический fallback `SECRET_KEY`, неправильный `postgres://` URL, дубли классов конфигурации, отсутствие стандартного URI SQLAlchemy. | Использовать `DATABASE_URL`, нормализовать PostgreSQL URL, не использовать производственный fallback ключа; для локальной разработки предусмотреть SQLite. Выполнено. |
| Критично | `run.py` | Встроенный сервер запускался с `debug=True` и `0.0.0.0`. | По умолчанию выключить debug и слушать localhost; разрешить debug только явной переменной `FLASK_DEBUG=true`. Выполнено. |
| Критично | `app/models.py`, `database/db.sql` | ORM не соответствовал DDL: неверные имена таблиц, некорректные `Column`/`column`, отсутствующие типы и ссылки на несуществующие классы/поля. Создание metadata могло завершаться ошибкой. | Переписать модели по таблицам и типам из `database/db.sql`; привести имена PK/FK к схеме. Выполнено для сущностей, описанных в SQL-файле. |
| Критично | `app/blueprints/auth.py` | Вложенная функция `login` затеняла endpoint, проверки делались по классу `Users`, а не по найденному пользователю; поля и ответы обращались к несуществующим атрибутам. | Вынести обработчики на уровень Blueprint, корректно обрабатывать `None`, использовать `password_hash`, добавить валидацию и запрет самостоятельного назначения роли администратора. Выполнено. |
| Важно | `app/__init__.py` | Фабрика импортировала параллельные и нерабочие View-модули, регистрировала маршруты только при наличии URI, проверяла БД и вызывала `create_all()` при каждом запуске. | Использовать единый factory, зарегистрировать исправленные web/auth Blueprint, добавить health endpoint; `create_all()` оставить только для локальной SQLite-разработки. Выполнено. |
| Важно | `app/blueprints/web.py` | Вход обращался к `Users` вместо `user`, имена шаблонов не совпадали с файлами, раздача изображений строила путь вручную. | Исправить проверку пользователя, связать маршруты с существующими шаблонами, использовать `send_from_directory`. Выполнено. |
| Важно | `requirements.txt`, `README.md` | Список зависимостей был пустым, README не содержал инструкции запуска. | Зафиксировать прямые runtime-зависимости и добавить инструкцию настройки/запуска. Выполнено частично: версии ограничены диапазонами, но не lock-файлом. |
| Рекомендация | `app/blueprints/`, `app/views/`, `app/services/`, `app/repository/` | В проекте остались дублирующие legacy-реализации API и сервисов; часть модулей содержит неправильные импорты/несогласованные контракты. Исправленная фабрика не подключает эти legacy View-модули. | Следующим этапом выбрать одну архитектуру API, перенести нужные CRUD-маршруты в неё, удалить дубли после регрессионных тестов. Не подключать старые View-модули до исправления. |
| Рекомендация | `tests/`, `docs/` | В исходном архиве нет автоматизированных тестов и Postman-коллекции; интеграционные сценарии не покрыты. | Добавить pytest-тесты для регистрации, входа, блокировки, CRUD и прав доступа; завести тестовую БД и CI. |

Приоритет «Критично» означает, что замечание блокирует безопасный запуск или базовую работу приложения. «Важно» — нарушает ключевой сценарий или устойчивость. «Рекомендация» — требует отдельного этапа архитектурной и регрессионной работы.
